# Как запустить ИОЗ-231 без постоянно включённого компьютера

## 1. Опубликовать проект

1. Зарегистрируй бесплатную учётную запись на https://github.com/ и подтверди email.
2. Создай новый **публичный** репозиторий `ioz231` с веткой `main`.
3. Распакуй ZIP на компьютере. Через **Add file → Upload files** загрузи содержимое папки, **не сам ZIP**. В корне должны находиться `docs`, `data`, `scripts`, `tests`, `requirements.txt`, `README.md` и **`.github/workflows/update.yml`**. На macOS включи показ скрытых файлов: Cmd+Shift+точка. Если `.github` не загрузилась, создай путь `.github/workflows/update.yml` вручную в редакторе GitHub и скопируй файл из архива.
4. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**. **Не выбирай Deploy from a branch**: в данном архиве обновлённый сайт публикуется явным шагом workflow.

## 2. Настроить чтение VK

1. Создай своё VK-приложение через кабинет разработчика VK и получи сервисный ключ доступа, подходящий для чтения публичной стены (`wall.get`). Не нужен токен сообщества `dekanat_ign` — ты не администратор этой группы.
2. GitHub: **Settings → Secrets and variables → Actions → New repository secret**; Name: `VK_TOKEN`, Secret: твой сервисный ключ. Нажми **Add secret**.
3. Никогда не добавляй сам токен в публичный код, README, переписку или URL, который раздаёшь одногруппникам. Если токен отозван/истёк, замени его в этом же разделе.

## 3. Запустить проверку

1. GitHub: **Actions → Обновление и публикация ИОЗ-231 → Run workflow → Run workflow**.
2. Открой запущенную задачу и проверь, что зелёными отмечены шаги: тесты, «Проверить таблицу и публикации VK», «Сохранить актуальные данные», «Опубликовать обновлённый сайт».
3. Если сообщение о запрете `git push`, открой **Settings → Actions → General → Workflow permissions**, выбери `Read and write permissions` (если доступно) и перезапусти.
4. Открой **Settings → Pages → Visit site**. Для репозитория `ioz231` адрес обычно `https://ТВОЙ_ЛОГИН.github.io/ioz231/`.
5. На iPhone открой сайт в Safari → «Поделиться» → «На экран Домой».

## После настройки

Сценарий проверки запускается по расписанию раз в 15 минут в облаке GitHub и заново публикует сайт. Компьютер включать не нужно. Это **не** гарантия проверки точно в минуту: GitHub может задержать/пропустить задачу. При отсутствии активности репозитория более 60 дней scheduled workflows могут быть отключены; контролируй журнал **Actions**.

Текущая версия автоматически применяет только однозначные **текстовые** отмены, переносы и замены аудиторий для ИОЗ-231. Сведения в фотографиях/сканах и неоднозначных сообщениях требуют человеческой проверки. Если Mail не даёт загрузить обновлённый Excel, остаётся последняя сохранённая таблица. При наличии надёжной прямой ссылки на файл добавь `XLSX_DIRECT_URL` как второй репозиторный secret.

Если на сайте написано «Изменения ВКонтакте пока не подключены», значит последнее чтение VK не было успешным. Если написано «Excel пока не удалось перепроверить» — база занятий сохранена, но невозможно подтвердить, что файл на Mail не изменился. Удобно сверять статусы раз в неделю.

**Ничего вручную публиковать после каждого поста VK не требуется, но полностью безошибочное распознавание всех форматов постов текущая версия не обеспечивает.**
