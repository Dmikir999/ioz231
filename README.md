# Расписание ИОЗ-231 — МГПУ

## Подключение следующего семестра

Откройте `semester.json` на GitHub и нажмите карандаш. В `source` вставьте публичную ссылку Облака Mail на новый XLSX, в `sheet` — название листа. В `periods` укажите по порядку интервалы занятий в формате `["ГГГГ-ММ-ДД", "ГГГГ-ММ-ДД"]`, оставляя перерывы между ними. Сохраните через **Commit changes**. В разделе **Actions** откройте запуск «Обновление и публикация ИОЗ-231»: зелёная галочка означает успешную публикацию, при ошибке откройте красный шаг для пояснения. Предыдущая публикация доступна, пока импорт нового семестра не пройдёт проверки. Поддерживается текущий шаблон института (группы в C7/D7, дни и время в A/B, даты занятий в тексте). Если для нового файла используется та же публичная ссылка, обновите или удалите устаревший секрет XLSX_DIRECT_URL.


Минимальное мобильное веб-приложение **строго для ИОЗ-231** с реальным расписанием из файла «Расписание 1 полугодия 2026–2027. Историки.xlsx». Источник — [Облако Mail](https://cloud.mail.ru/public/TKBt/bHWaZqMQA), сообщения об изменениях — [деканат ИГН VK](https://vk.ru/dekanat_ign).

## Новая цель проекта (обновлено 9 ноября 2026 года)

**Сделать бесплатное, простое веб-расписание только для ИОЗ-231, которое автоматически публикует подтверждённые данные из университетской таблицы и однозначные изменения из ВКонтакте, а в остальных случаях ясно предупреждает о неполной или устаревшей информации.**

Главная ценность — **доверие к информации**, а не обещание абсолютной автономности. Пользователь должен видеть занятия, время, преподавателя и аудиторию, понимать, что именно проверено, и при необходимости быстро перейти к официальному источнику.

### Правила принятия решений

1. **Только ИОЗ-231.** Данные других групп не отображаются; общие занятия показываются только если они действительно относятся к ИОЗ-231.
2. **Без догадок.** Автоматически изменять пару можно только если группа, дата, исходное время и тип изменения однозначны и найдена ровно одна исходная пара.
3. **Неоднозначное ≠ подтверждённое.** Фото, файлы, смешанные группы и спорные сообщения должны отмечаться для сверки; они не изменяют занятия автоматически.
4. **Честная свежесть.** Успех публикации сайта не равен успеху проверки Excel и VK; статусы источников должны отображаться раздельно. При сбое использовать последнюю сохранённую версию, предупредив о риске устаревания.
5. **Прослеживаемость и откат.** У автоматически изменённой пары должна быть ссылка на пост-источник; оригинальные записи сохраняются для восстановления.
6. **Бесплатность и простота.** Сайт без обязательной регистрации, удобный на iPhone, облачный запуск без включённого компьютера и без платных API.

### Критерии готовности

- [x] Сайт показывает реальные занятия только ИОЗ-231 из загруженного Excel.
- [x] Неоднозначные текстовые изменения VK не применяются автоматически.
- [x] Есть отдельные видимые признаки доступности исходной таблицы и VK.
- [ ] Проверен доступ к реальному VK API с рабочим токеном и выполнен контрольный импорт реальных изменений.
- [ ] Протестированы реальные объявления с фотографиями/вложениями и определён безопасный сценарий их обработки.
- [ ] Разделены фактическое время последней успешной проверки VK и время публикации сайта.
- [ ] Настроено оповещение владельца о продолжительном сбое проверок и новый семестр.
- [ ] Подтверждена работа опубликованного GitHub Pages и автоматической публикации в течение нескольких недель.

Это **неофициальный студенческий справочник**, а не замена объявлениям деканата.

## Что готово

- **149 занятий ИОЗ-231** с датами, временем начала и окончания, преподавателями, видом занятия и аудиториями. Лист «4иоз», колонка C, без расписания ИОЗ-232.
- В таблице две группы имеют общие лекции, а часть предметов вынесена отдельно. Импорт распознаёт общие пары и исключает сегменты «для группы ИОЗ-232».
- Сайт для смартфона: недели, дни, «Сегодня», отметки дней с занятиями, отмены, переносы, ссылка на источники. Никакой авторизации у одногруппников.
- Обновления через GitHub Actions + VK API каждые **15 минут**; ПК не требуется.
- Однозначные текстовые посты VK с конкретной датой и временем могут автоматически отменять/переносить ровно одну существующую пару или менять аудиторию. Неоднозначные сообщения отмечаются как требующие проверки и **не портят расписание**.
- При недоступности Mail остаётся подтверждённая версия, созданная на основе загруженного Excel. Прямой обновлённый XLSX, если получится скачать по публичной ссылке, импортируется заново.

## Как сразу посмотреть

Открой файл `ИОЗ-231_расписание_просмотр.html`, который поставляется отдельно от ZIP. Это **автономный предпросмотр**: всё основное расписание уже внутри, интернет не нужен. Данные в таком локальном файле не обновляются.

## Бесплатное размещение и запуск — один раз

1. Создай публичный репозиторий на GitHub, например `ioz231`.
2. Загрузи **содержимое** этой папки в репозиторий, сохранив скрытую папку `.github/workflows`.
3. Открой **Settings → Pages**. В разделе **Build and deployment → Source** выбери **GitHub Actions** (не «Deploy from a branch»). Сайт будет публиковаться отдельным шагом того же облачного сценария. Адрес будет похож на `https://ЛОГИН.github.io/ioz231/`.
4. Для автоматического чтения постов VK создай своё VK-приложение в кабинете разработчика VK и получи **сервисный ключ доступа**. Для публичной стены обычно подходит именно сервисный ключ; токен стороннего сообщества не нужен. Проверь, что ключ имеет доступ к `wall.get`. Добавь ключ в **Settings → Secrets and variables → Actions → New repository secret**, имя **`VK_TOKEN`**. Никогда не загружай ключ в код сайта и не присылай его в чат.
5. Если GitHub требует разрешить запись для `GITHUB_TOKEN`, открой **Settings → Actions → General → Workflow permissions** и выставь **Read and write permissions** (если опция доступна); сохрани. Открой вкладку **Actions → Обновление и публикация ИОЗ-231 → Run workflow → Run workflow**. Дождись зелёной галочки у всех шагов, включая **«Опубликовать обновлённый сайт»**. Планировщик затем запускается без участия пользователя примерно каждые 15 минут; GitHub может задерживать проверки.
6. Открой **Settings → Pages → Visit site** и проверь, что видны занятия ИОЗ-231 и нет предупреждения об отключённом VK. Только после успешной проверки отправь ссылку одногруппникам.


**Важно:** в ZIP намеренно **нет исходного XLSX с другими группами**. Вместо него — `data/base.json`, уже содержащий только занятия ИОЗ-231. При изменении общевузовского Excel приложение попробует скачать обновлённую таблицу с Mail; но неофициальный диспетчер этого сервиса может не работать. Если у тебя появится прямая ссылка на скачивание XLSX (не страница просмотра), добавь её как secret `XLSX_DIRECT_URL` — она имеет приоритет.

## Ограничения и честный статус

- На момент сборки **реальные посты VK не удалось проверить**, токена нет, поэтому **переносы и отмены VK не применены**. Сайт честно сообщает об этом. Поддержка чтения VK запустится лишь после настройки и успешного обращения к API.
- Если в посте только **картинка**, либо группа указана только во вложенном файле, автоматический импорт этой информации пока не поддерживается. Для этого необходим OCR и дополнительные проверки. Текстовые посты с указанием ИОЗ-231, содержащие вложения, попадают в «Требуют проверки».
- Неоднозначные или сложные формулировки также требуют проверки; полностью безошибочную автоматизацию любых будущих постов гарантировать нельзя.
- GitHub может задерживать cron, а в публичных репозиториях после 60 дней без активности отключать планировщик. Ежедневный штамп проверки обычно создаёт коммит, пока сценарий выполняется, но отсутствие перебоев навсегда не гарантируется. Проверяй состояние **Actions** хотя бы раз в месяц.
- В исходном листе дата учебных занятий указана **01.09–05.10 и 03.11–30.12.2026**. Расписание второго полугодия после 30 декабря нужно будет импортировать отдельно.

## Проверка разработчиком

Нужен Python 3.10+; сторонние библиотеки не требуются.

```bash
python -m unittest discover -s tests -v
python -m scripts.engine
python -m http.server 8000 --directory docs
```

Открой `http://localhost:8000`. При локальном запуске без токена будет использоваться проверенный `base.json`, а в предупреждении честно указано, что VK не подключён. Для проверки парсера реального файла в Python:

```python
from scripts.xlsx_reader import parse_xlsx
import json
from datetime import date
config = json.load(open("semester.json", encoding="utf-8"))
periods = [(date.fromisoformat(a), date.fromisoformat(b)) for a, b in config["periods"]]
lessons, warnings = parse_xlsx(open("Расписание 1 полугодия 2026-2027. Историки.xlsx", "rb").read(), config["sheet"], periods)
print(len(lessons), warnings)
```

Используется Python standard library; платные API, хостинг и база данных не нужны. Для начала автоматической работы требуется **однократное размещение и настройка токена VK**, которые невозможно выполнить от твоего имени без доступа к аккаунтам.
